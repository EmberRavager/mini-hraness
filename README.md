# Mini Harness：从一次决策读懂整个循环

**助手不是模块。** 助手负责决定下一步；模块是让决定能安全执行的代码。这里有两种角色，但只有一个模型入口和一个循环：

| 助手 | 能做什么 | 不能做什么 |
|---|---|---|
| 主助手 | 列文件、读、申请写、调用白名单命令、委派、返回答案 | 绕过写审批、运行任意命令，或在一次任务中启动第 7 个子助手 |
| 子助手 | 列文件、读、返回子任务结果 | 写文件、执行命令、继续委派；不会自动看到父助手的对话 |

**读代码顺序**：`harness.py:run` 看谁决定 → `workspace_tools.py:call_tool` 看谁动手 → 回到 `run` 看结果写回谁的历史。最后看 `cli.py:main` 如何接真实模型。六次委派是总额度，不是六个并发线程。

先运行 `python3 -m unittest -v`（在本目录，无需模型）。从 `test_page` 看起：主 Agent 委派写标题 → 子 Agent 越权写入被拒 → 返回 HTML → 主 Agent 提前结束被拒 → 写入、读回、结束。这是**回放模型响应**，实际的循环、权限判断、文件状态和验收没有 mock。

接着读 `harness.py` 的 `run()`：**模型提议 → 保存待执行动作 → harness 检查并执行 → 结果放回历史 → 下一轮**。子 Agent 不是另一个框架：压入一个只有新目标和空历史的栈帧；完成时弹栈，把它的回答当作父级 `delegate` 的返回值。

| 仓库 Chat Harness 的八项职责 | 本例的最小落点 |
|---|---|
| Context Manager | 每轮只给当前目标、最近六组动作与结果、允许的动作；不是 token 级裁剪。 |
| Agent Loop | 一个 `while`，每轮至多提议一个动作。 |
| Tool Executor | `workspace_tools.py` 注册并执行当前角色可用的工具：列出、读取、写入虚拟文件，以及固定命令 `word_count`（将内容送入 `/usr/bin/wc -w`，不调用 Shell）。错误回填给模型。 |
| State & Memory | 一个检查点保存栈、文件、剩余预算和待执行动作；没有跨任务记忆。 |
| Orchestrator | CLI 装配模型、审批、存档；父子共享循环和预算，不开后台 Worker。 |
| Guardrails | 写前询问、扁平文件名、子级只读且不能再委派、步数和截止时间。 |
| Observability | 终端显示当前角色和动作；检查点 `trace` 保留父子轨迹，不随模型历史裁剪。 |
| Evaluator | 离线回放检查控制行为；运行时 `--expect` 只检查指定文件非空，否则交给人工验收。 |

模块名对应 `agent-web/src/pages/documentation/chatHarnessModuleReference.js`，不是八个类，也不等于生产实现。例子只面向可信本机、单进程、一个运行目录；不提供多租户隔离、任意 Shell 或外部工具重试。

**快捷启动**：先启动本地 Ollama，确保已安装 `qwen3.5:4b-q4_K_M`。启动器从随项目提供的 `.env.example` 读取公开模型名，不读取真实 `.env`。在本目录运行：

```sh
./start.sh
# 或者直接给任务和验收文件：
./start.sh '请委派子 Agent 设计页面，再写 index.html：按钮切换深浅色，不要用外部资源。' --expect index.html
```

可用 `--model 模型名` 临时覆盖默认值。检查点与产物保存在启动时的工作目录。核对写入预览，确认后在打印的产物目录找到 `index.html`。文件非空不等于交互正确；检查生成的代码后，用浏览器点两次按钮验证能否切换回来。`Ctrl-C` 可中断，在同一目录用 `./start.sh --resume` 继续；原截止时间不会重置。
